# Generic Fallback Proxy

[![CI](https://github.com/sch-chun/astrbot_plugin_generic_fallback/actions/workflows/ci.yml/badge.svg)](https://github.com/sch-chun/astrbot_plugin_generic_fallback/actions/workflows/ci.yml)

Плагин AstrBot, предоставляющий универсальный OpenAI-совместимый прокси-сервис на базе цепочек резервных провайдеров.

## Возможности

- **Виртуальные модели**: объединяют несколько провайдеров в одну виртуальную модель с единым OpenAI-совместимым эндпоинтом
- **Цепочка резервирования**: провайдеры перебираются в порядке приоритета; при ошибке автоматически используется следующий
- **Механизм кулдауна**: после неудачного запроса провайдер уходит в кулдаун, длительность которого растёт по настраиваемой шкале «последовательных ошибок»
- **Ручное отключение**: любой провайдер можно отключить/включить в панели мониторинга в любой момент; отключённые узлы не участвуют в резервировании
- **Журнал вызовов**: в панели мониторинга доступны последние записи вызовов по каждому провайдеру (время, успех/ошибка, причина ошибки)
- **Пользовательские правила**: для каждого провайдера можно задать правила, срабатывающие при последовательном совпадении текста ошибки N раз — кулдаун или отключение
- **Поддержка потоковой передачи**: полная поддержка проксирования SSE-потоковых ответов
- **Проверка API Key**: опциональная аутентификация самого прокси-слоя
- **Метки моделей**: опционально добавляет `[Имя провайдера]` в начало текста ответа, чтобы отслеживать, какая модель была использована
- **Панель мониторинга**: встроенная веб-страница состояния с кулдауном и конфигурацией виртуальных моделей
- **Многоязычность**: параметры конфигурации и панель мониторинга доступны на 简体中文 / English / 日本語 / Русский и переключаются вместе с языком панели AstrBot; этот README тоже есть на четырёх языках

## Установка

Установите по ссылке в панели управления AstrBot (https://github.com/sch-chun/astrbot_plugin_generic_fallback) или клонируйте вручную в каталог плагинов:

```bash
cd AstrBot/data/plugins
git clone https://github.com/sch-chun/astrbot_plugin_generic_fallback.git
```

## Конфигурация

После установки задайте в конфигурации плагина в панели управления следующие параметры:

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `proxy_host` | string | `127.0.0.1` | Адрес прослушивания прокси; рекомендуется оставить локальным |
| `proxy_port` | int | `3474` | Порт прослушивания прокси |
| `proxy_api_key` | string | (пусто) | API Key прокси-слоя; при пустом значении проверка не выполняется |
| `empty_response_max_attempts` | int | `3` | Число повторов при пустом ответе; после превышения выполняется резервирование без учёта как последовательная ошибка (в потоковом режиме повторы и переключение завершаются до отправки первого байта контента; если все провайдеры недоступны, возвращается 503 — как и в нестриминговом режиме) |
| `cooldown_policy` | list | `[[1, 1], [2, 5], [5, 30]]` | Шкала кулдауна при последовательных ошибках, см. ниже |
| `call_log_max_per_provider` | int | `200` | Число записей журнала на провайдера; каждый провайдер хранит свои последние N записей независимо. 0 отключает журнал |
| `virtual_models` | list | (см. ниже) | Список конфигураций виртуальных моделей |

### Конфигурация virtual_models

Каждая виртуальная модель содержит:

- **display_name**: имя виртуальной модели, используемое клиентами (например `my-fallback`); старое поле `name` по-прежнему поддерживается
- **provider_ids**: провайдеры цепочки резервирования, в порядке убывания приоритета
- **timeout**: таймаут запроса в секундах, по умолчанию 120

> ⚠️ Внимание: не выбирайте саму виртуальную модель в provider_ids (плагин автоматически отфильтрует циклические ссылки и предупредит).

### Конфигурация cooldown_policy

`cooldown_policy` — вложенный список, где каждый элемент равен `[число последовательных ошибок, минуты кулдауна]`, в порядке возрастания числа ошибок:

```json
[[1, 1], [2, 5], [5, 30]]
```

Это означает: **1 ошибка** → кулдаун **1 минута**, **2–4 ошибки** → **5 минут**, **5 и более ошибок** → **30 минут**.
Кулдаун уровня действует до достижения порога следующего уровня; если число ошибок ниже первого порога, применяется первый уровень (например `[[3, 10]]` означает кулдаун 10 минут независимо от числа ошибок).

- Успешный запрос **сбрасывает** счётчик последовательных ошибок провайдера.
- Допустимы дробные минуты (например `0.5` = 30 секунд); `0` означает отсутствие кулдауна.
- Также принимается эквивалентная JSON-строка (например `"[[1, 1], [2, 5]]"`).
- Исчерпание повторов при пустом ответе, `completion has no choices`, фильтрация по безопасности контента и 415 `Unsupported Media Type` **не учитываются и не вызывают кулдаун** — происходит только переключение на следующего провайдера (последние два случая — явный отказ вышестоящего сервиса, повторять бессмысленно, и провайдер не должен наказываться). **Потоковый и нестриминговый режимы ведут себя одинаково**: в потоковом режиме `completion has no choices` тоже повторяется на месте, а после исчерпания повторов происходит только переключение без кулдауна.
- Некорректная конфигурация (не список, элемент не из двух значений, порог не положительное целое или дублируется, минуты отрицательные или не число) регистрируется в логе как ошибка и **сбрасывается к значению по умолчанию** `[[1, 1], [2, 5], [5, 30]]`.

### Пользовательские правила

Помимо встроенной шкалы кулдауна, в панели мониторинга можно настроить **необязательные правила для каждого провайдера**: если причина ошибки содержит заданный фрагмент (без учёта регистра), это считается одним совпадением; при достижении порога последовательных совпадений срабатывает одно из трёх действий — кулдаун на заданное число минут, кулдаун до 00:00 следующего дня или отключение.

Правила управляются кнопкой «Правила» на карточке провайдера в панели мониторинга. Каждое правило содержит:

- **Текст совпадения**: фрагмент кода или сообщения об ошибке (например `429`, `quota`), не более 100 символов;
- **Число**: сколько последовательных совпадений требуется для срабатывания (положительное целое; успешный запрос сбрасывает счётчик);
- **Действие**: `Кулдаун на минуты` (допустимы дробные минуты) / `Кулдаун до 00:00 следующего дня` / `Отключить`;
- **Часовой пояс** (только для «Кулдаун до 00:00»): пусто или `local` — локальное время; `UTC` / `GMT` — всемирное время; поддерживаются записи с префиксом, например `UTC+8`, `UTC +8`, `GMT-5.5`, `UTC+05:30` (двоеточие = минуты, `.5` = полчаса); можно указать и смещение в часах от UTC напрямую (например `-8`, `+9`, `+5.5`). Квота сбрасывается в 00:00 указанного часового пояса; у разных провайдеров в цепочке квоты часто сбрасываются в разных поясах, поэтому это значение задаётся для каждого правила отдельно.

Особенности поведения:

- При срабатывании правила **встроенная шкала кулдауна пропускается** (кулдаун не накапливается по cooldown_policy), управление берёт на себя действие правила;
- Правила и текущее число совпадений (`совпадения/порог`) показаны в модальном окне правил; правила, достигшие порога, подсвечиваются;
- Правила хранятся в KV плагина и восстанавливаются автоматически после перезапуска AstrBot; одно некорректное правило отбрасывается без влияния на остальные;
- Добавление/изменение/удаление отправляется через `POST /generic_fallback/rules/set` (семантика полной замены). Эндпоинт использует аутентификацию панели AstrBot и требует входа; поле `custom_rules` эндпоинта `status` возвращает правила каждого провайдера и текущие счётчики совпадений.

## Использование

### Настройка провайдера в AstrBot

После запуска плагина заполните настройки провайдера OpenAI в AstrBot:

- **API Base URL**: `http://127.0.0.1:3474/v1` (скорректируйте под proxy_host/proxy_port)
- **API Key**: значение, заданное в `proxy_api_key` (если не задано, можно оставить пустым — но провайдер OpenAI требует непустое значение, поэтому укажите любой заполнитель, например `no-key`)
- **Имя модели**: имя виртуальной модели из virtual_models (например `my-fallback`)

### Внешние вызовы

Прокси предоставляет стандартные OpenAI-совместимые эндпоинты:

```bash
# Список виртуальных моделей
curl http://127.0.0.1:3474/v1/models

# Чат-завершение
curl http://127.0.0.1:3474/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-proxy-api-key" \
  -d '{"model": "my-fallback", "messages": [{"role": "user", "content": "Привет"}]}'

# Проверка состояния
curl http://127.0.0.1:3474/v1/status
```

## Мониторинг

Плагин содержит встроенную панель мониторинга, доступную на странице плагина в панели управления AstrBot. Она показывает состояние кулдауна, число последовательных ошибок и конфигурацию виртуальных моделей для каждого провайдера.

У каждой карточки провайдера есть кнопка **Отключить / Включить**:

- После отключения провайдер немедленно перестаёт участвовать в резервировании (статус «Отключён») до ручного включения;
- Включение одновременно очищает его кулдаун и счётчик последовательных ошибок;
- Состояние хранится только в памяти — после перезагрузки плагина или перезапуска AstrBot все провайдеры снова доступны.

В верхней части панели показана действующая шкала кулдауна (например `1 ошибка→1 мин, 2 ошибки→5 мин, 5 ошибок→30 мин`).

У каждой карточки провайдера также есть кнопка **Журнал** для просмотра последних вызовов:

- Каждая запись содержит время вызова, успех/ошибку и причину ошибки (например явный отказ вышестоящего сервиса, повторные пустые ответы);
- Данные хранятся только в памяти: последние N записей для каждого провайдера отдельно (по умолчанию 200, настраивается через `call_log_max_per_provider`, без вытеснения друг друга); очищаются при перезагрузке плагина или перезапуске AstrBot;
- Записи читаются через `GET /generic_fallback/logs?provider_id=...`, эндпоинт использует аутентификацию панели AstrBot и требует входа.

У каждой карточки провайдера также есть кнопка **Правила** для управления пользовательскими правилами:

- Список правил показывает текст совпадения, условие срабатывания и текущее число совпадений (`совпадения/порог`); правила, достигшие порога, подсвечиваются;
- В модальном окне можно добавлять, изменять и удалять правила; значок «Правила ×N» на карточке показывает текущее число правил;
- Нажмите «Сохранить», чтобы применить изменения; закрытие без сохранения вызывает предупреждение об отмене изменений.
