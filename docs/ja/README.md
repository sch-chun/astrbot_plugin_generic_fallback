# Generic Fallback Proxy

[![CI](https://github.com/sch-chun/astrbot_plugin_generic_fallback/actions/workflows/ci.yml/badge.svg)](https://github.com/sch-chun/astrbot_plugin_generic_fallback/actions/workflows/ci.yml)

Provider のフォールバックチェーンに基づく、汎用の OpenAI 互換プロキシサービスを提供する AstrBot プラグインです。

## 機能

- **仮想モデル**：複数の Provider を 1 つの仮想モデルにまとめ、統一された OpenAI 互換エンドポイントを公開します
- **フォールバックチェーン**：優先度順に Provider を試し、失敗すると自動的に次へ切り替えます
- **クールダウン機構**：Provider のリクエストが失敗するとクールダウンに入り、その長さは「連続失敗回数」の段階に応じて増加します（段階はカスタマイズ可能）
- **手動無効化**：監視パネルからいつでも Provider を無効化／解除できます。無効化されたノードはフォールバックに参加しません
- **呼び出しログ**：監視パネルで Provider ごとの直近の呼び出し記録（時刻、成否、失敗理由）を確認できます
- **カスタムルール**：Provider ごとに任意のルールを設定でき、エラーメッセージが指定文字列に連続 N 回一致するとクールダウンまたは無効化を発動します
- **ストリーミング対応**：SSE ストリーミングレスポンスのプロキシを完全サポートします
- **API Key 検証**：プロキシ層自身の API Key 認証を任意で有効化できます
- **モデルラベル**：レスポンス文本の先頭に `[Provider名]` を挿入でき、実際に使用されたモデルの追跡に役立ちます
- **監視パネル**：クールダウン状態と仮想モデル設定を確認できる Web ステータスページを内蔵しています
- **多言語対応**：設定項目と監視パネルが簡体字中国語 / English / 日本語 / Русский に対応し、AstrBot パネルの言語に自動で切り替わります。この README も 4 言語で提供しています

## インストール

AstrBot 管理パネルのリンク（https://github.com/sch-chun/astrbot_plugin_generic_fallback）からインストールするか、プラグインディレクトリに手動でクローンします：

```bash
cd AstrBot/data/plugins
git clone https://github.com/sch-chun/astrbot_plugin_generic_fallback.git
```

## 設定

インストール後、管理パネルのプラグイン設定で以下を設定します：

| 設定項目 | 型 | 既定値 | 説明 |
|--------|------|--------|------|
| `proxy_host` | string | `127.0.0.1` | プロキシの待受アドレス。ローカルのまま推奨 |
| `proxy_port` | int | `3474` | プロキシの待受ポート |
| `proxy_api_key` | string | (空) | プロキシ層の API Key。空の場合は検証なし |
| `empty_response_max_attempts` | int | `3` | 空応答の再試行回数。超過すると連続失敗に含めず次の Provider へフォールバック（ストリーミングでは再試行とフォールバックは最初のコンテンツバイト送信前に完了。全 Provider が利用不可の場合は非ストリーミングと同様に 503 を返します） |
| `cooldown_policy` | list | `[[1, 1], [2, 5], [5, 30]]` | 連続失敗クールダウン段階。後述 |
| `call_log_max_per_provider` | int | `200` | Provider ごとのログ保持件数。各 Provider が互いに影響せず直近 N 件を保持します。0 でログを保持しません |
| `virtual_models` | list | (後述) | 仮想モデル設定一覧 |

### virtual_models の設定

各仮想モデルには以下が含まれます：

- **display_name**：クライアントがリクエストで使用する仮想モデル名（例：`my-fallback`）。旧設定の `name` フィールドも引き続き利用可能です
- **provider_ids**：フォールバックチェーンとして選択する Provider。優先度の高い順に並べます
- **timeout**：リクエストのタイムアウト（秒）、既定値 120

> ⚠️ 注意：provider_ids に仮想モデル自身を選択しないでください（プラグインが循環参照を自動的に除外し警告します）。

### cooldown_policy の設定

`cooldown_policy` は入れ子のリストで、各項目は `[連続失敗回数, クールダウン分数]` であり、失敗回数の昇順に並べます：

```json
[[1, 1], [2, 5], [5, 30]]
```

これは「連続失敗 **1 回**で **1 分**、**2〜4 回**で **5 分**、**5 回以上**で **30 分**クールダウン」を意味します。
ある段階のクールダウン時間は次の段階のしきい値に達するまで有効です。失敗回数が最初のしきい値未満の場合は最初の段階を適用します（例：`[[3, 10]]` は失敗回数に関係なく 10 分クールダウン）。

- リクエストが成功すると、その Provider の連続失敗回数は**ゼロに戻ります**。
- クールダウン分数は小数も使用できます（例：`0.5` は 30 秒）。`0` はクールダウンなしを意味します。
- 同等の JSON 文字列も受け付けます（例：`"[[1, 1], [2, 5]]"`）。
- 空応答の再試行使い切り、`completion has no choices`、コンテンツセーフティフィルタ、415 `Unsupported Media Type` の場合は**回数にもクールダウンにも含めず**、次の Provider へフォールバックするだけです（後者 2 つは上流側の明確な拒否であり、再試行に意味がないため Provider を罰しません）。**ストリーミングと非ストリーミングで動作は同一**です：ストリーミングでも `completion has no choices` はその場で再試行し、再試行使い切り後はフォールバックのみ（クールダウンなし）です。
- 設定が不正（リストでない、項目が 2 要素でない、しきい値が正の整数でない／重複、分数が負または数値でない）の場合、プラグインはログにエラーを出力し**既定値** `[[1, 1], [2, 5], [5, 30]]` に**戻します**。

### カスタムルールの設定

組み込みのクールダウン段階に加えて、監視パネルで **Provider ごとに任意のカスタムルール**を設定できます：失敗理由に指定文字列（大小文字を区別しない）が含まれると 1 回の命中として数え、連続命中がしきい値に達すると、「指定分数のクールダウン」「翌日 00:00 までクールダウン」「無効化」のいずれかを発動します。

ルールは監視パネルの Provider カードにある「ルール」ボタンで管理します。各ルールには以下が含まれます：

- **一致文字列**：エラーコードやエラーメッセージの断片（例：`429`、`quota`）、最大 100 文字；
- **連続回数**：発動までに連続で命中する回数（正の整数。成功するとカウンターはゼロに戻ります）；
- **発動動作**：`指定分数のクールダウン`（分数は小数可）／ `翌日 00:00 までクールダウン` ／ `無効化`；
- **タイムゾーン**（「翌日 00:00 までクールダウン」のみ）：空欄または `local` でローカルタイム、`UTC` / `GMT` で協定世界時。接頭辞付きのオフセット表記も可能で、例：`UTC+8`、`UTC +8`、`GMT-5.5`、`UTC+05:30`（コロンは分、`.5` は 30 分）。UTC からのオフセット時間を直接入力しても構いません（例：`-8`、`+9`、`+5.5`）。指定タイムゾーンの翌日 00:00 に上限がリセットされます。フォールバックチェーン内の異なる事業者は異なるタイムゾーンでリセットされることが多いため、ルールごとに設定できます。

動作の説明：

- ルールが命中すると、**組み込みのクールダウン段階はスキップ**され（cooldown_policy による累加なし）、ルールの動作が優先されます；
- ルールとリアルタイム命中数（`命中/しきい値`）はルールモーダルに表示され、しきい値に達したルールはハイライトされます；
- ルールはプラグイン KV に保存され、AstrBot 再起動後に自動復元されます。個々のルールが不正な場合でもそのルールのみ破棄され、他のルールには影響しません；
- 追加・編集・削除は `POST /generic_fallback/rules/set` で送信されます（全体置換セマンティクス）。このエンドポイントは AstrBot パネル認証を使用するため、ログインが必要です。`status` エンドポイントの `custom_rules` フィールドで各 Provider のルールとリアルタイム命中数を読み取れます。

## 使い方

### AstrBot で Provider を設定する

プラグイン起動後、AstrBot の OpenAI プロバイダー設定に以下を入力します：

- **API Base URL**：`http://127.0.0.1:3474/v1`（proxy_host/proxy_port に合わせて調整）
- **API Key**：`proxy_api_key` に設定した値（未設定の場合は空欄でも可ですが、OpenAI プロバイダー側で空欄が許可されないため、`no-key` などの適当な値を入力してください）
- **モデル名**：virtual_models で設定した仮想モデルの name（例：`my-fallback`）

### 外部からの呼び出し

プロキシは標準の OpenAI 互換エンドポイントを提供します：

```bash
# 仮想モデル一覧
curl http://127.0.0.1:3474/v1/models

# チャット補完
curl http://127.0.0.1:3474/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer your-proxy-api-key" \
  -d '{"model": "my-fallback", "messages": [{"role": "user", "content": "こんにちは"}]}'

# 状態確認
curl http://127.0.0.1:3474/v1/status
```

## 監視

プラグインには監視パネルが内蔵されており、AstrBot 管理パネルのプラグインページから確認できます。各 Provider のクールダウン状態、連続失敗回数、仮想モデル設定が表示されます。

各 Provider カードには**無効化／解除**ボタンがあります：

- 無効化すると、その Provider は手動で解除されるまでフォールバックに参加しません（状態は「無効」と表示）；
- 解除すると、クールダウンと連続失敗回数も同時にクリアされます；
- この状態はメモリにのみ保存され、プラグインのリロードや AstrBot の再起動後はすべて有効に戻ります。

パネル上部には現在有効なクールダウン段階が表示されます（例：`1 回→1 分、2 回→5 分、5 回→30 分`）。

各 Provider カードには**ログ**ボタンもあり、クリックするとその Provider の直近の呼び出し記録を確認できます：

- 各記録には呼び出し時刻、成否、失敗理由（上流側の明確な拒否、連続する空応答など）が含まれます；
- データはメモリにのみ保存され、Provider ごとに直近 N 件を保持します（既定値 200、`call_log_max_per_provider` で調整可能、互いに押し出しません）。プラグインのリロードや AstrBot の再起動でクリアされます；
- 記録は `GET /generic_fallback/logs?provider_id=...` で読み取り、このエンドポイントは AstrBot パネル認証を使用するためログインが必要です。

各 Provider カードには**ルール**ボタンもあり、クリックするとその Provider のカスタムルールを管理できます：

- ルール一覧には各ルールの一致文字列、発動条件、リアルタイム命中数（`命中/しきい値`）が表示され、しきい値に達したルールはハイライトされます；
- モーダル内でルールの追加・編集・削除ができ、カードの「ルール ×N」バッジに現在のルール数が表示されます；
- 変更後は「保存」を押すと反映されます。保存せずに閉じると変更が破棄された旨が警告されます。

## テスト

プラグインディレクトリで実行します（`pytest` と `pytest-asyncio` のインストール、および AstrBot ディレクトリの `PYTHONPATH` への追加が必要です）：

```bash
pytest -q
```
